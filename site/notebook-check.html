Notebook check

This site was built from the class notebook From Graphs to Hubs (Ch2_4_Applied_Tutorial.ipynb). Its code and its claims were re-checked one by one. This page lists everything that needed a correction or a caveat, with its exact location in the notebook.

How it was checked

  1. Re-execution. Every code cell was run again, in order, on the book's data, and each printed number and table was compared with the output saved in the notebook. All of them are reproduced exactly; the code does what it says.
  2. Independent recomputation. Every quantity was recomputed with this site's own JavaScript graph and statistics library, which is tested against NetworkX, igraph, SciPy and powerlaw.
  3. Review of the reasoning. Each statement was checked against a derivation, a simulation or the data. Comparisons with the book (Chapters 2–5 of Network Science) and with the standard methodology (Clauset, Shalizi & Newman 2009) were used as cross-checks, not as proof. The book has errors of its own, listed below.

The verdict: the computations are right, and most of the text is too. The problems are a sampling shortcut that is biased at small $k_{\min}$, a missing goodness-of-fit step in the power-law analysis, one confounded experiment, and a number of statements that generalise from one network or need a qualification. The site's pages present the corrected versions, each marked with a Correction to the notebook box.

Locations: cell counts cells from the top of the notebook (cell 1 is the title). In [n] is the execution count saved with a code cell.

The list

Problems found in the book

The book was not taken as ground truth either. Its results were re-derived or simulated, and its tables recomputed from the data files it distributes. These are the places where it is wrong, inconsistent, or does not match its own data.

Problems found in the software

The notebook relies on the Python package powerlaw (version 2.0.0). Cross-checking this site's goodness-of-fit test turned up two defects in its discrete random generators. They do not change any of the notebook's outputs, but they do bias the bootstrap test, which the notebook omits (N14), for anyone who adds it with powerlaw's own generator.
